Cloud Spanner

Relational, Global, Horizontally Scalable

Fully managed relational database: scales horizontally, strongly consistent, speaks SQL.

Horizontal vs vertical scaling

Raise the load, then scale each way.

HORIZONTAL: add or remove servers
VERTICAL: one instance, bigger or smaller
Synchronous replication

Click a zone to write an update. It is instantly copied to the others. Take a zone offline: data is still served.

Especially suited for applications that need
  • A SQL relational DBMS with joins and secondary indexes
  • Built-in high availability (minimal or zero downtime)
  • Strong global consistency
  • Database sizes that exceed 2 TB
  • Tens of thousands of reads/writes per second or more
Firestore

Documents, Collections, Offline Sync

NoSQL document store, ideal for mobile and web: flexible, scales horizontally, indexed by default. A document is a record. A collection is like a table.

Relational (Spanner, Cloud SQL)

Table → rows (records) → columns (fields). Queried with SQL.

Firestore

Collection → documents (records) → field–value pairs, like JSON. Queried with NoSQL queries: filter and sort.

Collection students

Click a document to see it as field–value pairs.

Offline persistence demo

Go offline, make changes, reconnect.

Bigtable

Massive Scale, Low Latency

Google's NoSQL big data database service. Powers Search, Analytics, Maps and Gmail. Good for IoT, user analytics and financial data analysis.

Fast and performant

High performance under high loads, low latency, high throughput.

Seamless scaling

Billions of rows, thousands of columns. No downtime during reconfiguration; replication adds availability.

Fully managed

Google handles configuration and tuning; backups for disaster recovery.

Integrated

Works with open-source big data tools (Hadoop and similar).

Terms to Know

Worded from the slides wherever possible.

TermMeaning
Cloud SpannerFully managed relational database: scales horizontally, strongly consistent, speaks SQL.
Horizontal scalingScale by adding and removing servers.
Vertical scalingMake a single instance larger or smaller.
Strong consistencyA read returns the value of the most recent completed write; copies are kept up-to-date and identical.
Synchronous replicationData is instantly copied across zones/regions when updated.
Secondary indexAn extra index on a table to speed lookups; Spanner supports joins and secondary indexes.
High availabilityContinuous access with minimal or zero downtime.
IOPSInput/output operations per second; Spanner suits tens of thousands of reads/writes per second or more.
FirestoreNoSQL document database for mobile and web: flexible, horizontally scalable.
DocumentA data record of field–value pairs, like a JSON object.
CollectionA group of documents; like a table.
Field–value pairOne named field with its value inside a document.
Indexed by defaultFirestore indexes each document automatically.
Offline persistenceFirestore caches data so apps work offline, then syncs local changes on reconnect.
Cloud BigtableFully managed NoSQL big data service: low latency, high throughput, billions of rows.
NoSQLNon-relational databases, usually for unstructured data; Firestore and Bigtable.
BigQuerySQL data warehouse for analytical workloads; used later for AI/ML tasks.
Transactional vs analyticalFrequent app reads/writes vs large-scale analysis of big data.
