Definition

So, What's the Cloud Anyway?

The class anchors on the NIST definition (SP 800-145). Know it cold.

Cloud computing is a model for enabling ubiquitous, convenient, on-demand network access to a shared pool of configurable computing resources (e.g., networks, servers, storage, applications, and services) that can be rapidly provisioned and released with minimal management effort or service provider interaction.

The model is composed of:

5essential characteristics
3service models
4deployment models

Locations, Regions & Zones

A geographic location contains regions; a region contains zones (usually 3, with the odd exception of 4). Zones are where your resources actually run. Click a zone to knock it out.

REGION: europe-west2 (London)
Why it matters: spreading resources across zones gives resource redundancy. Some services also run multi-region (e.g., across London and Belgium within Europe).

Vocabulary

Terms to Know

Worded from the slides wherever possible.

TermMeaning
NISTNational Institute of Standards and Technology, the source of the cloud definition (SP 800-145).
Cloud computingA model for on-demand network access to a shared pool of configurable computing resources that can be rapidly provisioned and released with minimal management effort.
On-demand self-serviceResources on demand, automatically, with no human needed at the provider.
Broad network accessResources reached over the internet, from anywhere.
Resource poolingThe provider allocates resources from a shared pool; it buys in bulk and location doesn't matter to you.
Rapid elasticityResources scale up or down quickly as needed.
Measured servicePay only for what you use or reserve. Stop using, stop paying.
Deployment modelsNIST says there are four. The slides give only the number.
IaaSInfrastructure as a Service: you provision fundamental resources and control the OS, storage and deployed apps. Pay for what you allocate.
PaaSPlatform as a Service: you deploy apps onto provider-supported languages, libraries and tools. Pay for what you use.
SaaSSoftware as a Service: you use the provider's application over the internet.
Thin clientA lightweight interface, such as a web browser, used to reach a SaaS app.
Location / region / zoneLocations contain regions; regions contain multiple zones; zones are where resources are deployed.
Multi-regionA service that runs across geographic locations, e.g., London and Belgium.
Resource redundancyRunning resources across several zones so one zone failing doesn't take you down.
Internet exchangeA point where Google's network meets the public internet (90+).
Point of presence (PoP)Another interconnection point with the public internet (110+ worldwide).
Cloud ShellThe browser-based command line used in the labs (gcloud runs here).

Cheat Sheet

The Five-Minute-Before-The-Exam Version

NIST in one line

Shared pool of configurable resources, on-demand over the network, rapidly provisioned and released with minimal effort.

5 characteristics

On-demand self-service · Broad network access · Resource pooling · Rapid elasticity · Measured service.

Service models

IaaS = you run OS + apps (EC2, Compute Engine, VMs). PaaS = you run code (Elastic Beanstalk, App Engine, App Services). SaaS = you just use it (Gmail, Zoom).

Payment

IaaS: pay for what you allocate. PaaS: pay for what you use.

Google layers

Compute · Storage · Big Data & ML, all on Networking & Security.

Geography

Location → Region → Zones. Resources deploy in zones; spread across zones for redundancy. 43 regions, 130 zones.
