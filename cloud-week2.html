Elastic Apps

Autoscaling: Add Servers, Remove Servers

In a managed instance group, autoscaling adds VMs when average CPU utilization goes above the max target and removes them when it drops below the min target. Targets here: 75% max, 45% min. Drag the demand, then run the autoscaler.

Instances: · average utilization: · target range: 45–75%
The math from the slides. Scale-out: four VMs at 100/100/85/100% = 385/400 = 96.25%. +1 VM gives 385/500 = 77% (still above 75%), +2 gives 385/600 = 64.2%, so add two. Scale-in: six VMs totaling 205/600 = 34%. −1 gives 41% (still below 45%), −2 gives 51%, so remove two.

Cheat Sheet

The Five-Minute-Before-The-Exam Version

Compute options

Compute Engine (IaaS) · App Engine (PaaS) · GKE (hybrid) · Cloud Run (serverless platform) · Cloud Functions (serverless logic).

Compute Engine

VMs with a full OS. Set CPU, memory, storage, OS. Create via Cloud Console or gcloud. Pay for what you allocate.

Autoscaling

Above max target (75%): scale out. Below min target (45%): scale in. Utilization = total load ÷ (instances × 100).

App Engine

Fully managed PaaS: no servers, auto scaling and load balancing, built-in datastore, memcache, logging, auth.

Standard

Preconfigured containers. Specific Java, Python, PHP, Go, Node.js, Ruby versions. Must obey the sandbox.

Flexible

Custom containers. Custom runtime and OS via Docker image or Dockerfile. Instances restarted weekly.
