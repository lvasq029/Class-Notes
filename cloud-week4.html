Security in the Cloud

Five Layers of Infrastructure Security

Google Cloud is designed with security in mind, and it gives five different layers of protection to keep customers' data safe. Pick a layer.

Shared Responsibility

The Shared Security Model

Security responsibilities are shared between the customer and Google Cloud. The more managed the service, the more Google takes on. ■ customer-managed, ■ Google-managed.

Encryption

Google Cloud Encryption Options

A spectrum from limited control and simple to more control and more complex, plus a fourth option off to the side.

Encrypted by default, in transit and at rest
Client→ TLS →Google Cloud network / App Engine→ AES-256 →Cloud Storage

In transit: TLS (transport layer security). At rest: AES-256 bit keys.

IAM

Who Can Do What on Which Resources

IAM policies answer three questions. Who: a Google Account, a Google group, a service account, or a Cloud Identity domain. What: defined with an IAM role. Which: a resource in the hierarchy.

Policy inheritance

Click a node to grant a role there. Everything highlighted inherits it.

Cloud Identity

Define user and group policies with the Google Admin Console. Use the same credentials as existing Active Directory or LDAP systems; disable accounts when people leave.

Identity-Aware Proxy

Controls access to cloud-based applications and VMs by verifying user identity, and passes identity info to the app.

Cheat Sheet

The Five-Minute-Before-The-Exam Version

Five layers

Hardware infrastructure · Service deployment · Storage services · Internet communication · Operational security.

Defaults

TLS in transit, AES-256 at rest, with no action needed.

Key options

Default → CMEK (Cloud KMS) → CSEK (you supply keys) are more control and more complexity. Client-side = encrypt before upload.

Customer always owns

Content, access policies, usage, even in managed services.

IAM policy

Who can do what on which resources. Inherited down Organization → Project → resources.

Roles

Basic (Viewer, Editor, Owner, Billing admin) · Predefined (job-based) · Custom (your exact permissions).
