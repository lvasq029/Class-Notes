The Premise

A Transmission From 2040

This course is narrated from 2040, looking back at the cryptography of 2026 — the last generation designed before large quantum computers. Adversaries in your present are recording encrypted traffic they cannot read, betting that in ten to fifteen years they can. We in 2040 know how that bet paid off.

Harvest now, decrypt later: every ciphertext you transmit in 2026 should be assumed archived. The only question is whether it still matters when it finally opens. Your job this semester: judge which of these secrets reach 2040.

Field Note

Why the Box Is Called Subspace

  • Real mathematics: a subspace is a subset of a vector space closed under addition and scaling. Linear algebra had the word first.
  • Codes are subspaces: a linear [n,k] error-correcting code is a k-dimensional subspace over a finite field.
  • That is a PQC standard: HQC, the code-based backup NIST picked alongside ML-KEM in 2025, rests on exactly that. Coordinate λ.
  • Quantum uses it too: a quantum code protects states inside a code subspace; a decoherence-free subspace is one noise cannot reach.

What Cryptography Is

The four promises the era believed it could keep.

Cryptography: securing information by transforming it so only intended parties can use it. Cryptanalysis: defeating those transformations without the key. Cryptology: the umbrella over both — this course lives mostly in the first, visits the second constantly.

Etymology: kryptós (hidden) + gráphein (to write). The Greeks named it; we kept their alphabet for the math.

Confidentiality

Only authorized parties can read it. Encryption's home turf.

Integrity

Nobody altered it in transit or at rest. Hashes and MACs.

Authenticity

It really came from who it claims. Signatures, certificates.

Non-repudiation

The sender cannot deny sending it. Digital signatures + law.

What cryptography could not do:
  • No endpoint rescue — malware on the laptop reads plaintext before encryption ever happens.
  • No metadata cloak — who talked to whom, when, how much, is often visible even when content is not.
  • No policy substitute — perfect AES with the key taped to the monitor is zero-bit security.
  • No availability — encryption doesn't keep systems up; ransomware used the era's own crypto against it.

Kerckhoffs's principle: security must live entirely in the key, never in the secrecy of the algorithm. Crypto moves trust around. It never eliminates the need for it.

Historians confirm what 2026 only suspected: state actors and criminal syndicates were bulk-recording TLS traffic, VPN tunnels, and encrypted archives years before they could open them.

  • Passive collector: records — backbone taps, cloud snapshots, stolen encrypted databases.
  • Active adversary: interferes now — man-in-the-middle, replay, bit-flipping, downgrade.
Β

Hash Functions

One-way trips only.

  • Fixed-size digest: any input length in, constant length out (SHA-256: always 256 bits).
  • Deterministic: same input, same digest, every time, on every machine.
  • Avalanche effect: flip one input bit, roughly half the output bits flip.
  • Pre-image resistance: given a digest, infeasible to find any input that produces it.
  • Second pre-image resistance: given an input, infeasible to find a different input with the same digest.
  • Collision resistance: infeasible to find any two inputs with the same digest.

Hashing survived the quantum transition far better than public-key crypto did. Remember that asymmetry when we reach coordinate λ.

# same word, one capital letter — total digest chaos $ echo -n 'prequantum' | sha256sum 41ca5537... - $ echo -n 'Prequantum' | sha256sum 9f86d081... - # unrecognizable digest $ sha256sum archive.iso e3b0c442... archive.iso $ openssl dgst -sha3-256 entry-alpha.pdf

Verify downloads: digest match = integrity, not authenticity. Coordinate δ adds MACs so digests can prove origin too.

Collectors rarely attacked SHA-256's math. They precomputed digests of common passwords and looked yours up, or forged two documents sharing one digest and swapped them after signing. The Flame malware forged a Microsoft certificate from an MD5 collision in 2012 — fourteen years after MD5 was known weak.

  • Rainbow tables: precomputed hash lookups; defeated by salting every password with a unique random value.
  • Collision abuse: two contracts, one digest, one signature — the signature authenticates both.

Symmetric Cryptography

One key, both directions, blazing fast.

  • One shared secret: the same key encrypts and decrypts; anyone holding it can do both.
  • Speed: hardware AES moves gigabytes per second — why bulk data always travels symmetric.
  • The catch: both parties must already share the key securely, which is itself the hard problem.
  • Scaling pain: n people needing pairwise secrecy require n(n−1)/2 keys — 40 students = 780 keys.

Grover's algorithm halves effective symmetric key strength. AES-128 becomes 64-bit work; AES-256 becomes 128-bit. This is why symmetric crypto survived and RSA did not.

Block ciphers need a mode

AES encrypts 16 bytes at a time — a mode of operation is the recipe for chaining blocks into real messages.

  • ECB: each block independent; identical plaintext blocks produce identical ciphertext. Never use it — encrypt an image with ECB and the picture is still visible.
  • CBC: each block XORed with the previous ciphertext; needs a random IV; padding attacks lurk.
  • CTR: turns AES into a stream cipher via counters; parallel, fast, no padding.
  • GCM: CTR plus a built-in integrity tag — the mode TLS 1.3 actually requires. Full story at coordinate δ.
Δ

Asymmetric Cryptography

Two keys, one-way doors, and the trick that built the pre-quantum internet.

  • Key pair: a public key you publish freely, a private key you never share.
  • Encrypt to public: anyone can lock a message only the private key opens — confidentiality.
  • Sign with private: only you can produce a signature anyone can verify with the public key — authenticity.
  • Solves distribution: no shared secret needed in advance; the collector can watch the whole exchange.
  • The cost: hundreds to thousands of times slower than AES — it never carried the bulk data.

That last column is why harvest-now-decrypt-later was rational, and why your era migrated in a hurry.

Hybrid encryption: how it actually shipped
  1. Generate a random one-time symmetric session key.
  2. Encrypt the actual message with that session key using AES — fast.
  3. Encrypt only the tiny session key with the recipient's public key — slow but small.
  4. Send both; recipient unlocks the session key, then the message.

TLS, GPG email, Signal, disk escrow — all hybrid. Crack the asymmetric wrapper later, and the harvested symmetric bulk opens with it.

Constant across timelines: Symmetric for speed. Asymmetric for key exchange and identity. Hashes for integrity. Protocols glue them together — every seam is where the adversary gets in, and the asymmetric seam is the one that didn't survive the era.

Attacks: A Field Guide Preview

Coordinate η in miniature.

Brute force

Try every key. Defeated by key length — 2^128 outlives the sun. Worked fine on 56-bit DES.

Dictionary + rainbow

Humans picked words; attackers precomputed the likely ones. Salts + slow hashes were the answer.

Implementation flaws

Heartbleed leaked keys from perfect math. Padding oracles, timing leaks, bad RNG.

The human

Phished passphrases, keys in git repos, "temporary" debug backdoors. The eternal constant.

  • Cryptanalysis: linear and differential attacks shave bits off ciphers — mostly academic against AES.
  • Side channels: power draw, timing, sound, cache behavior leak keys without touching the math.
  • Protocol downgrade: POODLE forced servers back to broken SSL 3.0 — attack the negotiation, not the cipher.
  • Key management: the overwhelming majority of real breaches — stolen, leaked, or guessable keys.

Rule of thumb: in the entire pre-quantum record, almost nobody broke the vault door. They stole the key, copied the blueprints, or bribed the guard. Then quantum broke the door.
